# 2026-08-13 아침 — 딜레이 처방 매장 검증 체크리스트

8/12 에 딜레이 처방 12건이 라이브에 올라갔다 (`main` = `1933119`, Deploy web #8 성공).
아침에 이 순서대로만 하면 된다. **문제 생기면 5번 롤백 — 1~2분이면 원상복구.**

---

## 0. 준비 (1분)

**매장 PC**: 브라우저에서 **Ctrl + Shift + R** (그냥 F5 아님 — Service Worker 가
옛 번들을 물고 있어서 강력 새로고침이어야 갈아탄다).

**폰 / 안드로이드 탭**: 아래 한 줄로 OTA 발행 후, 앱 완전 종료 → 재시작 2번.
```bash
eas update --branch production --message "딜레이 전수조사 처방 12건"
```
> 첫 재시작에 다운로드, **두 번째 재시작에 적용**된다 (영업 중 강제 reload 안 하는 정책).
> 폰 검증은 급하지 않으면 PC 부터 확인하고 나중에 해도 된다.

## 1. 안 죽었는지 (30초) — 여기서 걸리면 바로 롤백

- [ ] 화면이 정상적으로 뜬다 (하얀 화면 / 크래시 화면 아님)
- [ ] 테이블 탭에 테이블 격자가 보인다
- [ ] 주문 탭에 메뉴가 보인다 (**메뉴가 사라졌으면 즉시 롤백** — B9 의심)
- [ ] 관리자 → 주소록에 주소 목록이 보인다 (**비었으면 즉시 롤백** — B1 의심)
- [ ] 관리자 → 수익현황에 오늘/이번달 숫자가 뜬다 (**0 이거나 빈 목록이면 즉시 롤백** — B3/B4 의심)

> 이 5개가 이번 수술이 건드린 곳이다. 여기만 무사하면 나머지는 성능 문제일 뿐 데이터 사고가 아니다.

---

## 2. 체감 속도 (5분)

- [ ] 테이블 탭에서 테이블 이리저리 눌러보기 — **버벅임이 줄었는지**
- [ ] 메뉴 담기 → 주문 확정 → 주방 화면 반영까지
- [ ] 안드로이드 탭에서도 같은 동작 (OTA 적용 후)

가장 크게 달라져야 할 곳: **아무것도 안 하고 가만히 둘 때.**
이전엔 깜빡임 타이머가 분당 100회 전체 리렌더를 돌려 상시 CPU 를 먹었다.

---

## 3. 부활 재현 시도 (5분) — 이번 처방의 핵심

- [ ] 카운터 PC 에서 테이블 하나 **결제 완료 / 치우기**
- [ ] 아이패드·주방 화면에서도 사라졌는지 확인
- [ ] **PC 새로고침 (Ctrl+Shift+R)** → 치운 테이블이 **안 돌아와야 정상**
- [ ] 아이패드 앱도 껐다 켜서 확인

> 여기서 되살아나면 두 가지 중 하나다.
> ① 디바운스 처방이 부족 → 진단 캡처 필요
> ② **이미 서버에 남아있던 좀비** (8/12 이전에 삭제가 못 올라간 것)
> 구분법: *오늘 새로 치운* 테이블이 살아나면 ①, *예전부터 계속 나오던* 테이블이면 ②.
> ② 는 이번 처방과 무관하며 그 건만 따로 지우면 된다.

## 5. 🚨 롤백 (문제 생겼을 때 — 1~2분)

**PC 없이 폰으로도 된다.**

1. GitHub → **Actions** 탭
2. 왼쪽 목록에서 **🚨 Rollback web**
3. **Run workflow** → ref 는 **기본값 그대로** → 초록 **Run workflow**
4. 1~2분 뒤 매장 PC **Ctrl + Shift + R**

기본값은 `bd799022...` = 8/6 매장 정상 확인분(딜레이 처방 들어가기 직전).

**폰 앱 롤백**은 별도다 — OTA 를 이미 발행했다면:
```bash
eas update --branch production --message "롤백"   # 직전 정상 커밋에서 실행
```
아직 OTA 발행 전이면 폰은 애초에 옛 버전이라 손댈 필요 없다.

> ⚠️ 롤백 워크플로는 **Cloudflare 에 올라간 것만** 되돌린다. `main` 브랜치는 그대로다.
> 불 끄고 나서 정리:
> ```bash
> git revert -m 1 1933119c6d32001ac54470b2b6e198602e27a473
> git push origin main
> ```
> 안 하면 다음 배포 때 문제 코드가 다시 올라간다.
