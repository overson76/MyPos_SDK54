# 아이폰 / 아이패드 Ad Hoc 배포

앱스토어에 **올리지 않고** 내 기기에만 설치하는 방법. 심사 없음, 공개 없음.

TestFlight(90일 만료) 를 대신하는 경로다. 사장님 기기 몇 대에만 넣고 쓰는 매장 운영에 맞는다.

## 왜 이 방식인가

| | Ad Hoc | TestFlight | App Store |
|---|---|---|---|
| 공개 | 등록한 기기만 | 초대한 사람만 | 전체 공개 |
| 만료 | **1년** (프로비저닝 프로파일) | 90일 | 없음 |
| 심사 | 없음 | 없음(내부) | 있음 |
| 기기 수 | 100대 / 계정 / 년 | 100명(내부) | 무제한 |

**전제**: Apple Developer Program 유료 멤버십($99/년). Ad Hoc 프로비저닝은 무료 계정으로 안 된다.

## 최초 1회 세팅

### 1. 기기 등록

```bash
npm run ios:device
```

`Website` 방식을 고르면 QR 코드가 뜬다. **등록할 아이폰/아이패드 카메라로 스캔** → 사파리가 열리고 프로파일 설치 안내가 나온다. 안내대로 설치하면 기기 UDID 가 Apple 개발자 계정에 등록된다.

여러 대면 기기마다 반복한다. 새 기기를 나중에 추가하면 **빌드를 다시 해야** 그 기기에 설치된다 (프로비저닝 프로파일에 UDID 가 박히기 때문).

### 2. 빌드

```bash
npm run ios:adhoc
```

Apple 로그인 → 인증서/프로파일은 EAS 가 알아서 만든다. 15~25분 걸린다.

끝나면 터미널에 **설치 링크 + QR** 이 나온다. 기기에서 그 링크를 열면 바로 설치된다. 앱스토어 안 거친다.

## 그 뒤 운영

### JS 만 고쳤을 때 — 재빌드 불필요

`adhoc` 프로필은 `channel: production` 이라 **정식 빌드와 같은 OTA 채널**을 탄다.

```bash
npm run ios:ota -- --message "설명"
```

기기가 다음 앱 시작 때 받고, 그 다음 시작에 적용된다 (`App.js` 가 강제 reload 안 함 — 영업 중 화면 튐 방지).

### 재빌드가 꼭 필요한 경우

- 네이티브 의존성 추가/변경
- `app.json` 의 `plugins` 변경
- `app.json` 의 `version` 변경 (runtimeVersion 정책이 `appVersion`)
- 새 기기 추가
- **1년 지나 프로파일 만료**

`buildNumber` 는 `eas.json` 의 `autoIncrement` 가 올려주므로 손댈 필요 없다.

## 1년 만료

프로비저닝 프로파일이 만료되면 앱이 안 열린다. TestFlight 90일보다 4배 길 뿐 만료 자체는 있다.

만료 한 달쯤 전에 `npm run ios:adhoc` 한 번 돌려서 새 링크로 재설치하면 된다. 캘린더에 걸어두는 걸 권장.

## 아예 만료 없는 대안

PWA. 사파리로 라이브 URL 열고 "홈 화면에 추가" — 만료도 갱신도 없고 배포할 때마다 자동 최신이다.

핀치 줌 정도만 네이티브 전용이라 그 차이가 신경 안 쓰이면 PWA 가 운영 부담이 가장 적다.
